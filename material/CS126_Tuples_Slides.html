Why Do We Need Tuples?

Some data should never change while the program runs:

  • The days of the week
  • The six GCC countries
  • The location of Kuwait City: (29.37, 47.98)
  • A date of birth: (15, 3, 2006)

With a list, one wrong line can change it by mistake:

days = ["Sun", "Mon", "Tue"]
days[0] = "Funday"     # oops!
print(days)
['Funday', 'Mon', 'Tue']
A tuple is like a list that is locked. Once it is created, no one can change, add, or remove its items.

Python will stop the program with an error if code tries to change a tuple — so mistakes are found early, not hidden.

What Is a Tuple?

A tuple is an ordered collection of values that cannot be changed (immutable).

gcc = ("Kuwait", "Qatar", "Oman")
( ) — round brackets (parentheses)
, — commas separate the items
items — any values, like in a list
locked — items cannot be changed
List
gcc = ["Kuwait", "Qatar", "Oman"]
Tuple
gcc = ("Kuwait", "Qatar", "Oman")
Same items, same order. The only visible difference is [ ] versus ( ) — but the behavior is different.

  • () is an empty tuple.

A Tuple with One Item Needs a Comma

Code
a = (5)
b = (5,)
print(a, type(a))
print(b, type(b))
Output
5 <class 'int'>
(5,) <class 'tuple'>
(5) is just the number 5 in brackets, like in math: (2 + 3) * 4.
A one-item tuple must have a comma: (5,)
Which of these are tuples?
x = ("Kuwait")
y = ("Kuwait",)
z = "Kuwait",
y and z are tuples. x is just the string "Kuwait".

The Big Difference: Tuples Cannot Change

List: allowed 
scores = [80, 90, 70]
scores[0] = 85
print(scores)
[85, 90, 70]
Tuple: error 
scores = (80, 90, 70)
scores[0] = 85
TypeError: 'tuple' object does not support item assignment

Tuples have no methods to add or remove items:

scores = (80, 90, 70)
scores.append(60)
AttributeError: 'tuple' object has no attribute 'append'
A tuple is immutable, like a string. A list is mutable.

"Changing" a Tuple = Making a New One

Join with +, repeat with *

a = (1, 2)
b = (3, 4)
print(a + b)
print(a * 3)
print(a)
(1, 2, 3, 4)
(1, 2, 1, 2, 1, 2)
(1, 2)

a did not change. + and * create new tuples.

Build a new tuple and reuse the name

days = ("Sun", "Mon", "Tue")
days = days + ("Wed",)
print(days)
days = ("Sat",) + days[1:]
print(days)
('Sun', 'Mon', 'Tue', 'Wed')
('Sat', 'Mon', 'Tue', 'Wed')
The old tuple is not changed. The name days now refers to a new tuple.

Functions and the Two Tuple Methods

Functions that read a tuple

prices = (2.5, 1.25, 4, 0.75)
print(len(prices))
print(min(prices), max(prices))
print(sum(prices))
4
0.75 4
8.5

They only read the tuple, so they work on both lists and tuples.

count() and index()

votes = ("yes", "no", "yes", "yes")
print(votes.count("yes"))
print(votes.index("no"))
3
1
  • count(x): how many times x appears.
  • index(x): position of the first x. If x is missing → ValueError.
  • These are the only tuple methods — neither one changes the tuple.

Converting: tuple() and list()

Code
t = (255, 128, 0)
lst = list(t)          # tuple -> list
lst[1] = 200           # lists can change
t = tuple(lst)         # list -> tuple
print(t)
print(tuple("KWT"))
Output
(255, 200, 0)
('K', 'W', 'T')

The 3-step pattern

  1. Convert the tuple to a list with list().
  2. Change the list.
  3. Convert back to a tuple with tuple().
Use this when you really must change locked data. If you need to change it often, a list is probably the better choice.

tuple("KWT") makes one item per character.

Unpacking: One Tuple, Many Variables

Code
student = ("Sara", 20, "CS")
name, age, major = student
print(name)
print(age)
print(major)
Output
Sara
20
CS
  • Each variable gets the item at the same position.
  • The number of variables must equal the number of items, otherwise → ValueError.

A Neat Trick: Swapping Two Variables

With a temporary variable

a = 3
b = 8
temp = a
a = b
b = temp
print(a, b)
8 3

With a tuple (one line)

a = 3
b = 8
a, b = b, a
print(a, b)
8 3
  1. The right side b, a builds the tuple (8, 3) first.
  2. Then it is unpacked: a gets 8, b gets 3.

A list of tuples

Which One Should I Use?

Use a tuple when…

  • The data must not change: months, GCC countries.
  • The values belong together as one record: a date (12, 10, 2026), a location (29.37, 47.98).
  • You want Python to protect the data from mistakes.

Use a list when…

  • Items will be added, removed, or changed: a shopping cart.
  • The number of items is not fixed: registered students.
  • You want to sort or edit the items.
List or tuple? (a) RGB color of the Kuwait flag green (b) a to-do list
(a) Tuple — three fixed values that form one color. (b) List — tasks are added and removed.

Common Mistakes (1): Creating Tuples

Incorrect 
colors = ("red")
print(type(colors))
print(len(colors))
<class 'str'>
3

Why? Without a comma, ("red") is just a string. len() counted its letters.

Correct 
colors = ("red",)
print(type(colors))
print(len(colors))
<class 'tuple'>
1
Incorrect 
days = ("Sun", "Mon")
days = days + "Tue"
TypeError: can only concatenate tuple (not "str") to tuple

Why? + joins a tuple with another tuple only.

Correct 
days = ("Sun", "Mon")
days = days + ("Tue",)
print(days)
('Sun', 'Mon', 'Tue')

Common Mistakes (2): Changing and Unpacking

Incorrect 
date = (12, 10, 2026)
date[0] = 13
TypeError: 'tuple' object does not support item assignment
Correct — build a new tuple 
date = (12, 10, 2026)
date = (13,) + date[1:]
print(date)
(13, 10, 2026)
Incorrect 
student = ("Sara", 20, "CS")
name, age = student
ValueError: too many values to unpack (expected 2)

Why? 3 items, but only 2 variables.

Correct 
student = ("Sara", 20, "CS")
name, age, major = student
print(name, age, major)
Sara 20 CS

Common Mistakes (3): Methods

Incorrect 
cart = ("rice", "tea")
cart.append("milk")
AttributeError: 'tuple' object has no attribute 'append'

Why? Tuples cannot grow. A shopping cart changes, so it should be a list.

Correct 
cart = ["rice", "tea"]
cart.append("milk")
print(cart)
['rice', 'tea', 'milk']
Incorrect 
gcc = ("Kuwait", "Qatar", "Oman")
print(gcc.index("Egypt"))
ValueError: tuple.index(x): x not in tuple
Correct — check first 
gcc = ("Kuwait", "Qatar", "Oman")
if "Egypt" in gcc:
    print(gcc.index("Egypt"))
else:
    print("Egypt is not in the tuple")
Egypt is not in the tuple

Worked Example 1: A Location

Code
# (latitude, longitude)
kuwait_city = (29.37, 47.98)
lat, lon = kuwait_city
print("Latitude:", lat)
print("Longitude:", lon)
if lat > 0:
    print("North of the equator")
else:
    print("South of the equator")
Output
Latitude: 29.37
Longitude: 47.98
North of the equator

Why a tuple?

  • A location is two values that belong together.
  • The city does not move, so the data should not change.
  • The position gives the meaning: first latitude, then longitude.

Step by step

  1. Unpacking puts 29.37 in lat and 47.98 in lon.
  2. 29.37 > 0 is True.

Worked Example 2: Updating a Student Record

Code — (ID, name, major)
record = (2026014, "Ali", "Math")
print("Before:", record)
# Ali changed his major to CS
record = record[:2] + ("CS",)
print("After:", record)
sid, name, major = record
print(name, "(" + str(sid) + ") studies", major)
Output
Before: (2026014, 'Ali', 'Math')
After: (2026014, 'Ali', 'CS')
Ali (2026014) studies CS

Step by step

  1. record[:2] is (2026014, 'Ali') — a new tuple.
  2. + ("CS",) joins a one-item tuple to it.
  3. The name record now refers to the new tuple.
  4. Unpacking gives three variables for a clear message.
The record can still be "updated" — but only on purpose, by building a new tuple. It cannot change by accident.

Worked Example 3: Days of the Week

Code
WEEK = ("Sun", "Mon", "Tue", "Wed", "Thu", "Fri", "Sat")
WEEKEND = ("Fri", "Sat")
today = "Thu"
num = WEEK.index(today)
tomorrow = WEEK[num + 1]
print(today, "is day", num + 1, "of", len(WEEK))
print("Tomorrow is", tomorrow)
if tomorrow in WEEKEND:
    print("Tomorrow is the weekend!")
Output
Thu is day 5 of 7
Tomorrow is Fri
Tomorrow is the weekend!
  1. index("Thu") is 4.
  2. The next day is at index 5 → "Fri".
  3. "Fri" in WEEKEND is True.
Names in CAPITAL letters are a common way to show values that are not meant to change. A tuple makes sure they cannot.

Think About It

1. If tuples cannot change, how does t = t + (4,) work?
It does not change the old tuple. It builds a new tuple and gives it the name t.
2. Why do tuples have only two methods, while lists have many?
Most list methods change the list (append, sort, …). Tuples cannot change, so only the "read" methods remain.
3. What does this print?
t = (4, 5, 6)
x, y, z = t
print(z, x + y, t[1:])
6 9 (5, 6)

What You Should Remember

  1. A tuple is an ordered collection in round brackets: (1, 2, 3). One item needs a comma: (5,).
  2. Tuples are immutable: no t[i] = x, no append, no remove.
  3. Reading works like lists: indexes, slices, len, in, min, max, sum.
  4. +, *, and slicing build new tuples.
  5. Only two methods: count() and index().
  6. Unpacking: a, b = (1, 2); swap with a, b = b, a.
  7. Tuple for fixed data; list for data that changes.
