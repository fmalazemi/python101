What Is a Set?

A set is a collection of unique items with no order.

gcc = {"Kuwait", "Qatar", "Oman"}
  • Curly brackets { } and commas.
  • Unique: each value appears at most once.
  • Unordered: items have no positions, so there are no indexes.
  • Mutable: you can add and remove items.
Think of a set as a bag: you can ask "is it in the bag?", but not "what is in position 1?"

  • set(...) converts a list, tuple, or string into a set — removing duplicates.
  • The empty set is written set().
{} is not an empty set. It makes a different type (a dictionary), which you will learn later.

  • A set keeps one copy of each value.
  • len(set(x)) = the number of different values.
  • From a string, each character becomes an item: "banana" → b, a, n.

Sets Have No Order and No Indexes

Error 
gcc = {"Kuwait", "Qatar", "Oman"}
print(gcc[0])
TypeError: 'set' object is not subscriptable

"Not subscriptable" means: you cannot use [ ] with it. No indexes, no slices.

Printing a set of strings
gcc = {"Kuwait", "Qatar", "Oman"}
print(gcc)
One possible output (order may differ)
{'Oman', 'Kuwait', 'Qatar'}
The printed order is not guaranteed. It may change between runs. Never depend on the order of a set.

Need a fixed order? Use sorted()

gcc = {"Kuwait", "Qatar", "Oman"}
print(sorted(gcc))
['Kuwait', 'Oman', 'Qatar']

sorted() gives a new sorted list. The set itself does not change.

  • in / not in — the main job of a set. Sets answer "is it in?" very fast, even with millions of items.

Adding Items: add() and update()

Code
ids = {101, 102}
ids.add(103)
ids.add(101)          # already there
print(ids)
ids.update([104, 105, 102])
print(ids)
print(len(ids))
Output
{101, 102, 103}
{101, 102, 103, 104, 105}
5
  • s.add(x) adds one item. If it is already there, nothing happens — no error, no duplicate.
  • s.update(other) adds every item of a list, tuple, or set.
  • Both change the set and return None, like list methods.
There is no append() or insert() — a set has no "end" and no positions.

Set Operations: Combining Two Sets

A = {1, 2, 3, 4}
B = {3, 4, 5, 6}
OperationOperatorMeaningResult
UnionA | Bin A or B{1, 2, 3, 4, 5, 6}
IntersectionA & Bin A and B{3, 4}
DifferenceA - Bin A, not in B{1, 2}
Symmetric differenceA ^ Bin exactly one{1, 2, 5, 6}
Each operation gives a new set. A and B do not change.

Union and Intersection

Code — two students' courses
sara = {"CS126", "MATH101", "ENG110"}
ali = {"CS126", "PHYS101", "ENG110"}
both = sara & ali
either = sara | ali
print(sorted(both))
print(sorted(either))
print(len(either))
Output
['CS126', 'ENG110']
['CS126', 'ENG110', 'MATH101', 'PHYS101']
4
  • Intersection &: courses they both take.
  • Union |: every course taken by at least one of them — each listed once.
  • Method versions do the same: sara.intersection(ali), sara.union(ali).
What does {1, 2} & {3, 4} give?
set() — the empty set. They have nothing in common.

Difference and Symmetric Difference

Code
sara = {"CS126", "MATH101", "ENG110"}
ali = {"CS126", "PHYS101", "ENG110"}
print(sara - ali)
print(ali - sara)
print(sorted(sara ^ ali))
Output
{'MATH101'}
{'PHYS101'}
['MATH101', 'PHYS101']
  • Difference A - B: in A but not in B. Courses only Sara takes.
  • Order matters for difference: sara - ali ≠ ali - sara.
  • Symmetric difference A ^ B: in one set but not both.
  • Methods: difference(), symmetric_difference().
Is A ^ B the same as (A | B) - (A & B)?
Yes. "Everything" minus "the shared part" = items in exactly one set.

Subsets: Is One Set Inside Another?

Code — graduation requirements
required = {"CS126", "MATH101"}
taken = {"CS126", "ENG110", "MATH101"}
print(required <= taken)
print(required.issubset(taken))
print(taken >= required)
missing = required - taken
print(len(missing))
Output
True
True
True
0
  • A <= B: every item of A is also in B (A is a subset of B).
  • A >= B: A contains all of B (A is a superset).
  • Method: A.issubset(B).
  • required - taken shows which requirements are missing.
Is {1, 2} <= {1, 2} True?
True. Every set is a subset of itself.

What Can Be Stored in a Set?

Allowed: immutable values 
s = {5, 2.5, "Kuwait", (29, 47), True}
print(len(s))
print((29, 47) in s)
5
True

Numbers, strings, and tuples can be set items.

Not allowed: mutable values 
s = {[29, 47]}
TypeError: unhashable type: 'list'

A list (or a set) cannot be an item in a set, because it could change after being stored.

"Unhashable" means "cannot be stored in a set". A good reason to use a tuple for a location!

Which One Should I Use?

List

  • Order matters.
  • Duplicates are meaningful.
  • Data changes.

A queue at the bank; daily temperatures.

Tuple

  • Order matters.
  • Data must not change.
  • One fixed record.

A date (12, 10, 2026); a GPS location.

Set

  • Each item only once.
  • Order does not matter.
  • Fast "is it in?" checks; comparing groups.

Unique visitors; courses in common.

Which one for: the countries a traveler has visited (no repeats needed)?
Set — visiting Doha twice still counts as one country, and order does not matter.

Common Mistakes (1): Empty Sets and Indexes

Incorrect 
visitors = {}
visitors.add("Ali")
AttributeError: 'dict' object has no attribute 'add'

Why? {} is an empty dictionary, not a set.

Correct 
visitors = set()
visitors.add("Ali")
print(visitors)
{'Ali'}
Incorrect 
ids = {101, 102, 103}
print(ids[0])
TypeError: 'set' object is not subscriptable

Why? Sets have no positions. If you need "the first" item, you need an order — use a list.

Correct 
ids = {101, 102, 103}
ordered = sorted(ids)
print(ordered[0])
101

Common Mistakes (2): Removing and Adding

Incorrect 
cart = {"rice", "tea"}
cart.remove("milk")
KeyError: 'milk'
Correct 
cart = {"rice", "tea"}
cart.discard("milk")
print(len(cart))
2
Incorrect 
tags = {"python"}
tags.add(["loops", "sets"])
TypeError: unhashable type: 'list'

Why? add() tries to store the list itself as one item, and lists are not allowed in sets.

Correct 
tags = {"python"}
tags.update(["loops", "sets"])
print(sorted(tags))
['loops', 'python', 'sets']

Common Mistakes (3): Strings and Sets

Incorrect 
# goal: a set with one city
cities = set("Kuwait")
print(len(cities))
6

Why? set("Kuwait") makes a set of characters: K, u, w, a, i, t.

Correct 
cities = {"Kuwait"}
print(len(cities))
1
Incorrect 
# goal: keep the visit order
visits = ["Ali", "Sara", "Ali", "Mona"]
unique = set(visits)
# then expect unique[0] to be "Ali" ...

Why? A set forgets the order. If order matters, a set is the wrong choice — keep the list.

Rule: use a set only when you do not care about order or how many times an item appears.

Worked Example 1: Unique Visitors

Code — visits to a café this week
visits = ["Ali", "Sara", "Ali", "Mona",
          "Sara", "Ali", "Fahad"]
people = set(visits)
print("Visits:", len(visits))
print("Different people:", len(people))
print("Ali came", visits.count("Ali"), "times")
if "Noor" not in people:
    print("Noor did not visit")
Output
Visits: 7
Different people: 4
Ali came 3 times
Noor did not visit

Step by step

  1. The list keeps every visit, including repeats.
  2. set(visits) keeps each person once: 4 people.
  3. To count repeats, use the list: visits.count("Ali").
  4. To check membership, use the set.
Each type does the job it is best at.

Worked Example 2: Comparing Course Schedules

Code
sara = {"CS126", "MATH101", "ENG110", "ARAB101"}
ali = {"CS126", "PHYS101", "ENG110"}
common = sara & ali
print("Study together:", sorted(common))
print("Only Sara:", sorted(sara - ali))
print("Only Ali:", sorted(ali - sara))
print("All courses:", len(sara | ali))
if len(common) >= 2:
    print("Good study partners!")
Output
Study together: ['CS126', 'ENG110']
Only Sara: ['ARAB101', 'MATH101']
Only Ali: ['PHYS101']
All courses: 5
Good study partners!
  1. & finds the shared courses.
  2. - in both directions finds each student's own courses.
  3. | joins both schedules, each course once: 4 + 3 − 2 shared = 5.
  4. sorted() prints in a fixed, readable order.

Worked Example 3: Food Allergy Check

Code — a restaurant dish
dish = {"rice", "chicken", "nuts", "milk"}
allergies = {"nuts", "eggs"}
problem = dish & allergies
if len(problem) > 0:
    print("Not safe:", sorted(problem))
else:
    print("Safe to eat")
allergies.discard("nuts")
print(len(dish & allergies))
Output
Not safe: ['nuts']
0

Why sets?

  • An ingredient is either in the dish or not — order and repeats do not matter.
  • One & compares the whole dish with all allergies at once.
  • An empty intersection (len == 0) means "nothing in common" — safe.

Think About It

1. Why can't sets have indexes?
Sets are unordered: there is no "first" or "second" item, so a position number has no meaning.
2. Why can a tuple be stored in a set, but a list cannot?
Set items must be immutable. A tuple cannot change; a list can.
3. What does this print?
s = {1, 2, 3}
s.add(2)
s.add(4)
s.discard(1)
print(len(s), 1 in s, sum(s))
3 False 9

The set is {2, 3, 4}: adding 2 again changes nothing.

What You Should Remember

  1. A set holds unique items with no order: {1, 2, 3}. Empty set: set(), not {}.
  2. set(x) removes duplicates from a list, tuple, or string.
  3. No indexes or slices. Use in, len, and sorted() when you need an order.
  4. add/update to add; remove (error if missing) or discard (no error) to delete.
  5. | union, & intersection, - difference, ^ symmetric difference — each gives a new set.
  6. Only immutable values (numbers, strings, tuples) can be set items.
  7. List: ordered, changeable. Tuple: ordered, fixed. Set: unique, unordered.
