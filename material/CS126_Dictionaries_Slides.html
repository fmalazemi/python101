Dictionaries

Looking up values by key — and how dictionaries differ from lists, tuples, and sets
Dr. Fawaz Alazemi

Learning Objectives

By the end of this lecture, you will be able to:

  1. Explain what a dictionary is: a collection of key → value pairs.
  2. Create dictionaries and read values with d[key] and d.get(key).
  3. Add, change, and remove pairs with d[key] = value, del, and pop().
  4. Use in, len(), keys(), values(), items(), and update().
  5. Know which values can be keys, and store lists or dictionaries as values.
  6. Avoid a KeyError.
  7. Choose between a list, tuple, set, and dictionary for a task.

Why Do We Need Dictionaries?

With two lists

names = ["Ali", "Sara", "Mona"]
phones = ["55512345", "66698765", "99911122"]
i = names.index("Sara")
print(phones[i])
66698765

We must find the position first, and keep both lists in the same order forever. One mistake and the numbers belong to the wrong people.

With a dictionary

phones = {"Ali": "55512345",
          "Sara": "66698765",
          "Mona": "99911122"}
print(phones["Sara"])
66698765
Look up the value directly by name. Each name is tied to its own number — like a real phone book.

What Is a Dictionary?

A dictionary stores pairs. Each pair has a key and a value. You use the key to find the value.

caps = {"Kuwait": "Kuwait City", "Qatar": "Doha"}
  • Curly brackets { }.
  • Each pair is written key: value with a colon.
  • Commas separate the pairs.
  • Keys are unique; values can repeat.
KeyValue
"Kuwait"→"Kuwait City"
"Qatar"→"Doha"
A real dictionary: look up a word (key) to find its meaning (value).

Code

d[key] = value does two jobs:

• key already there → replace its value

Compare: a list cannot grow with lst[5] = x (IndexError). A dictionary can.

Rules for Keys

1. Keys are unique — the last one wins

d = {"x": 1, "y": 2, "x": 3}
print(d)
print(len(d))
{'x': 3, 'y': 2}
2

2. Values may repeat

grades = {"Ali": "A", "Sara": "A"}
print(len(grades))
2

3. Keys must be immutable

Strings, numbers, and tuples can be keys — like set items.

places = {(29, 47): "Kuwait City"}
print(places[(29, 47)])
Kuwait City
places = {[29, 47]: "Kuwait City"}
TypeError: unhashable type: 'list'

Values have no such rule: they can be anything, even lists.

Looking Inside: keys(), values(), items()

Code
prices = {"tea": 0.25, "coffee": 1.0,
          "juice": 0.75}
print(list(prices.keys()))
print(list(prices.values()))
print(list(prices.items()))
print(sum(prices.values()))
print(max(prices.values()))
print(sorted(prices))
Output
['tea', 'coffee', 'juice']
[0.25, 1.0, 0.75]
[('tea', 0.25), ('coffee', 1.0), ('juice', 0.75)]
2.0
1.0
['coffee', 'juice', 'tea']
  • keys() → all keys; values() → all values.
  • items() → all pairs as tuples (key, value).
  • Wrap them in list() to print them clearly or use indexes.
  • sum(), max(), min() work on values().
  • sorted(d) gives the keys as a sorted list.

Merging Dictionaries: update()

Code — a price change and new items
menu = {"tea": 0.25, "coffee": 1.0}
changes = {"coffee": 1.25, "karak": 0.15}
menu.update(changes)
print(menu)
Output
{'tea': 0.25, 'coffee': 1.25, 'karak': 0.15}
  • a.update(b) copies every pair of b into a.
  • Keys only in b are added (karak).
  • Keys in both are replaced by b's value (coffee).
  • a changes; b does not.
It works like many a[key] = value lines at once.

Dictionaries as Lookup Tables

Instead of a long if / elif chain…

code = "QA"
if code == "KW":
    country = "Kuwait"
elif code == "QA":
    country = "Qatar"
elif code == "OM":
    country = "Oman"
else:
    country = "Unknown"
print(country)
Qatar

…use a dictionary

names = {"KW": "Kuwait",
         "QA": "Qatar",
         "OM": "Oman"}
code = "QA"
print(names.get(code, "Unknown"))
print(names.get("XX", "Unknown"))
Qatar
Unknown
Shorter, and adding a new country means adding one pair — not another elif.

A Useful Pattern: Counting with get()

Code — recording votes one by one
votes = {}
vote = "yes"
votes[vote] = votes.get(vote, 0) + 1
vote = "no"
votes[vote] = votes.get(vote, 0) + 1
vote = "yes"
votes[vote] = votes.get(vote, 0) + 1
print(votes)
Output
{'yes': 2, 'no': 1}

How the key line works

  1. votes.get(vote, 0): the current count, or 0 if this is the first time.
  2. + 1: one more vote.
  3. votes[vote] = …: store the new count (adds the key if needed).
With loops (later), this one line will count thousands of votes.

Common Mistakes (1): KeyError

Incorrect 
prices = {"tea": 0.25, "coffee": 1.0}
print(prices["juice"])
KeyError: 'juice'
Correct 
prices = {"tea": 0.25, "coffee": 1.0}
print(prices.get("juice", "not on the menu"))
not on the menu
Incorrect 
student = {"name": "Sara", "age": 20}
print(student[0])
KeyError: 0

Why? Dictionaries use keys, not positions. There is no key 0.

Correct 
student = {"name": "Sara", "age": 20}
print(student["name"])
Sara

Common Mistakes (2): in and Duplicate Keys

Incorrect 
# goal: is Doha one of the capitals?
caps = {"Kuwait": "Kuwait City",
        "Qatar": "Doha"}
print("Doha" in caps)
False

Why? in checks the keys. "Doha" is a value.

Correct 
caps = {"Kuwait": "Kuwait City",
        "Qatar": "Doha"}
print("Doha" in caps.values())
True
Incorrect 
# goal: two phone numbers for Ali
phones = {"Ali": "555", "Ali": "666"}
print(phones)
{'Ali': '666'}

Why? Keys are unique. The second "Ali" replaced the first.

Correct — make the value a list 
phones = {"Ali": ["555", "666"]}
print(phones["Ali"][1])
666

Common Mistakes (3): Keys and Views

Incorrect 
prices = {"tea": 0.25, "coffee": 1.0}
print(prices.keys()[0])
TypeError: 'dict_keys' object is not subscriptable

Why? keys() is not a list. Convert it first.

Correct 
prices = {"tea": 0.25, "coffee": 1.0}
print(list(prices.keys())[0])
tea
Incorrect 
user = {"Name": "Sara"}
print(user.get("name"))
None

Why? Keys are case-sensitive: "Name" ≠ "name". get() hides the problem by giving None.

Choose one style for keys (for example, all small letters) and use it everywhere.

Worked Example 1: A Restaurant Order

Code — prices in KD
menu = {"machboos": 3.5, "tea": 0.25,
        "juice": 0.75}
order = {"machboos": 2, "tea": 3}
total = menu["machboos"] * order["machboos"]
total = total + menu["tea"] * order["tea"]
print("Items ordered:", list(order.keys()))
print("Total:", total, "KD")
item = "kunafa"
if item not in menu:
    print(item, "is not on the menu")
Output
Items ordered: ['machboos', 'tea']
Total: 7.75 KD
kunafa is not on the menu

Step by step

  1. menu: item → price. order: item → quantity.
  2. The same key reads both: 3.5 × 2 = 7.0.
  3. 0.25 × 3 = 0.75, so the total is 7.75.
  4. not in checks the keys before using an unknown item.
The item name connects the two dictionaries — no positions needed.

Worked Example 2: Updating a Student Record

Code
student = {"id": 2026014, "name": "Noor",
           "credits": 45}
student["major"] = "CS"          # add
student["credits"] = student["credits"] + 15
old = student.pop("id")          # remove
print(student)
print("Removed ID:", old)
if student["credits"] >= 60:
    print(student["name"], "is a sophomore")
Output
{'name': 'Noor', 'credits': 60, 'major': 'CS'}
Removed ID: 2026014
Noor is a sophomore
  1. A new key "major" is added at the end.
  2. "credits" already exists, so its value is replaced: 45 + 15 = 60.
  3. pop("id") removes the pair and returns 2026014.
  4. The if reads a value by its key.
A record with named fields is clearer than a tuple: student["credits"] instead of student[2].

Worked Example 3: Currency Converter

Code — how many KWD for 1 unit (example rates)
to_kwd = {"USD": 0.3, "SAR": 0.08, "EUR": 0.35}
amount = 200
currency = "SAR"
if currency in to_kwd:
    result = amount * to_kwd[currency]
    print(amount, currency, "=", result, "KWD")
else:
    print("Unknown currency:", currency)
to_kwd["AED"] = 0.085
print(len(to_kwd), "currencies")
Output
200 SAR = 16.0 KWD
4 currencies
  • The dictionary is a lookup table: currency code → rate.
  • in protects against a KeyError for unknown codes.
  • Adding a new currency is one line — no new elif.

Rates here are simple examples, not today's real rates.

Think About It

1. Why can a tuple be a key, but a list cannot?
Keys must be immutable. If a key could change, Python could no longer find its value.
2. What is the difference between d["x"] = 5 on a dictionary and lst[9] = 5 on a short list?
The dictionary adds a new key if needed. The list gives an IndexError — it cannot grow this way.
3. What does this print?
d = {"a": 1, "b": 2}
d["c"] = d.get("a", 0) + d.get("z", 10)
print(d["c"], len(d), "z" in d)
11 3 False

get() never adds a key; it only reads.

What You Should Remember

  1. A dictionary stores key: value pairs in { }. Empty: {}.
  2. Read with d[key] (KeyError if missing) or d.get(key, default).
  3. d[key] = value adds a new pair or replaces an old value.
  4. Remove with del d[key] or d.pop(key).
  5. in and len() work on keys. Use d.values() to search values.
  6. Keys are unique and immutable; values can be anything.
  7. List/tuple: find by position. Set: unique items. Dictionary: find by key.
