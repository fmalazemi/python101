The in and not in Operators

Asking "Is it there?" in strings, lists, tuples, and sets
Dr. Fawaz Alazemi

Learning Objectives

By the end of this lecture, you will be able to:

  1. Explain what a membership operator is and what in and not in return.
  2. Use in with strings to search for characters and pieces of text.
  3. Use in with lists, tuples, and sets to search for whole items.
  4. Explain the difference between "text inside a string" and "item inside a list".
  5. Use in / not in inside if statements and with and, or, not.
  6. Replace long or chains with a single in test.
  7. Avoid common mistakes with case, spaces, types, and or.

Why Do We Need in?

Without in

day = "Sat"
if day == "Fri" or day == "Sat":
    print("Weekend")
Weekend

Now imagine checking a student ID against a class of 200 students with == and or…

With in

day = "Sat"
if day in ("Fri", "Sat"):
    print("Weekend")
Weekend
One short question: "Is day one of these?" It works the same way for 2 items or 2,000 items.

What Are in and not in?

They are membership operators. They ask whether a value is a member of (inside) a string or a collection.

ExpressionMeaningResult
x in cIs x inside c?True or False
x not in cIs x not inside c?True or False
print("a" in "cat")
print("z" in "cat")
print("z" not in "cat")
True
False
True
The result is a Boolean, so it can go anywhere a condition goes: an if, a variable, or a logical expression.

The Syntax

value in container
value not in container
value — what you are looking for
in / not in — the operator
container — a string, list, tuple, or set
Result — always True or False
not in is written as two words with a space, and it is one operator. It means exactly the opposite of in.

in with Strings: Looking for Text

Code
city = "Kuwait City"
print("K" in city)
print("wait" in city)
print("Wait" in city)
print("City" in city)
print("Ku City" in city)
print(" " in city)
Output
True
True
False
True
False
True
  • With a string, in looks for a substring: one character or several characters next to each other.
  • The search is case-sensitive: "Wait" is not "wait".
  • The characters must be together and in order: "Ku City" does not appear.
  • Spaces are characters too.
Both sides must be strings: 5 in "2026" → TypeError. Use "5" in "2026".

Lists Inside Lists

Code
data = [[1, 2], [3, 4]]
print([1, 2] in data)
print(1 in data)
print(1 in data[0])
print((1, 2) in data)
Output
True
False
True
False
  • The items of data are the lists [1, 2] and [3, 4].
  • 1 is not an item of data — it is inside an item. in does not look inside inner lists.
  • 1 in data[0] looks inside the first inner list.
  • A tuple is never equal to a list, so (1, 2) in data is False.

Common Mistakes (1): The or Trap

Incorrect 
day = "Mon"
if day == "Fri" or "Sat":
    print("Weekend")
Weekend

Why? Python reads (day == "Fri") or "Sat". A non-empty string like "Sat" counts as True, so the condition is always True.

Correct (two ways) 
day = "Mon"
if day == "Fri" or day == "Sat":
    print("Weekend")
if day in ("Fri", "Sat"):
    print("Weekend")
print("done")
done
The in version is shorter and cannot fall into this trap.

Common Mistakes (2): Case, Spaces, and Types

Incorrect 
cities = ["Kuwait", "Doha"]
city = "kuwait "
print(city in cities)
False

Why? Small "k" and an extra space — not an exact match.

Correct 
cities = ["Kuwait", "Doha"]
city = "kuwait "
print(city.strip().title() in cities)
True
Incorrect 
ids = ["101", "102", "103"]
print(102 in ids)
False

Why? The items are strings; 102 is a number.

Correct 
ids = ["101", "102", "103"]
print("102" in ids)
print(str(102) in ids)
True
True

Common Mistakes (3): String vs List, and Number in String

Incorrect 
# goal: does any GCC name contain "man"?
gcc = ["Kuwait", "Oman", "Qatar"]
print("man" in gcc)
False

Why? For a list, in checks whole items. No item equals "man".

Correct (check one item) 
gcc = ["Kuwait", "Oman", "Qatar"]
print("man" in gcc[1])
True
Incorrect 
year = "2026"
print(6 in year)
TypeError: 'in <string>' requires string as left operand, not int

Why? Searching a string needs a string on the left.

Correct 
year = "2026"
print("6" in year)
True

Worked Example 1: Checking an Email Address

Code
email = "Sara.Ali@KU.edu.kw".strip().lower()
has_at = "@" in email
has_space = " " in email
kuwaiti = ".kw" in email[-3:]
if not has_at or has_space:
    print("Invalid email")
elif kuwaiti:
    print("Valid Kuwaiti email:", email)
else:
    print("Valid email:", email)
Output
Valid Kuwaiti email: sara.ali@ku.edu.kw

Step by step

  1. Clean first: strip().lower().
  2. has_at → True; has_space → False.
  3. not True or False → False → not invalid.
  4. email[-3:] is ".kw" → Kuwaiti.
Boolean variables with clear names make the if read like a sentence.

Worked Example 2: A Café Order

Code
menu = ("tea", "coffee", "karak", "juice")
sold_out = {"juice"}
sizes = ("S", "M", "L")
drink = " Karak ".strip().lower()
size = "XL"
if drink not in menu:
    print("Sorry,", drink, "is not on the menu")
elif drink in sold_out:
    print("Sorry,", drink, "is sold out")
elif size not in sizes:
    print("Please choose size S, M, or L")
else:
    print("Order:", size, drink)
Output
Please choose size S, M, or L
  1. "karak" is on the menu → first test False.
  2. Not sold out → second test False.
  3. "XL" not in sizes → True → ask for a valid size.
A tuple for the fixed menu, a set for items that come and go.

Worked Example 3: Password Rules

Code
pw = "Kuwait2026"
common = ["123456", "password", "qwerty"]
digits = set("0123456789")
has_digit = len(set(pw) & digits) > 0
has_upper = pw.lower() != pw
too_common = pw.lower() in common
has_name = "kuwait" in pw.lower()
print(has_digit, has_upper, too_common, has_name)
if too_common or not has_digit or not has_upper:
    print("Weak password")
elif has_name:
    print("OK, but avoid place names")
else:
    print("Strong password")
Output
True True False True
OK, but avoid place names
  • in with a list: is the whole password a common one?
  • in with a string: does it contain "kuwait"?
  • Without loops, a set intersection checks for "any digit": the characters of pw that are also digits.

Think About It

1. Why is "wa" in "Kuwait" True, but "wa" in ["Kuwait"] False?
With a string, in looks for text inside it. With a list, it looks for a whole item equal to the value.
2. You check thousands of IDs for "is it allowed?". List or set?
Set — membership tests on a set are much faster than on a list.
3. What does this print?
t = ("a", ["b", "c"], "d")
print("b" in t, ["b", "c"] in t, "c" in t[1])
False True True

"b" is inside an item, not an item itself.

What You Should Remember

  1. x in c and x not in c always give True or False.
  2. With a string, in looks for a piece of text (substring).
  3. With a list, tuple, or set, in looks for a whole item that is equal.
  4. in does not look inside inner lists.
  5. Matches are exact: case, spaces, and type matter — clean first, then check.
  6. x in ("a", "b") replaces x == "a" or x == "b" — never write x == "a" or "b".
  7. Use a set when you do many membership tests.
