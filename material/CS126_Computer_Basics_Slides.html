What Is a Computer?

A computer is a machine that follows instructions to work with data.

A computer can:

  1. Take in data (input)
  2. Work on the data (process)
  3. Keep the data (store)
  4. Give back results (output)
A list of instructions for a computer is called a program. Writing programs is called programming.

Computers are everywhere

  • Laptops and desktop PCs
  • Mobile phones and tablets
  • ATMs and petrol pumps
  • Cars, smart TVs, and washing machines
  • Airport check-in machines

All of them follow programs written by people.

Hardware and Software

Hardware

The physical parts of a computer — things you can touch.

  • Keyboard, mouse, screen
  • Processor (CPU), memory chips
  • Hard disk or SSD

Software

Programs — instructions that tell the hardware what to do. You cannot touch them.

  • Operating system: Windows, macOS, Android
  • Applications: web browser, WhatsApp, Word
  • Your own programs, written in Python
Simple picture: hardware is the body; software is the thinking that tells the body what to do. One is useless without the other.

The CPU: The Brain of the Computer

CPU = Central Processing Unit (also called the processor).

  • It follows program instructions, one after another.
  • It does math (+ - × ÷) and comparisons (>, =).
  • It controls the other parts of the computer.
  • Speed is measured in GHz: 3 GHz ≈ 3 billion steps per second.
  • Modern CPUs have several cores — small processors that work at the same time.

The instruction cycle

This cycle repeats billions of times every second.

Analogy: RAM is your desk — small, but everything on it is ready to use. Storage is the cabinet — big, but you must take things out first.
This is why you must save your work: saving copies it from RAM to storage. If the power goes off before you save, the work in RAM is lost.

The Operating System (OS)

The operating system is the main program of a computer. It runs all the time and manages everything else.

  • Starts and stops other programs.
  • Gives each program a part of RAM and CPU time.
  • Manages files and folders in storage.
  • Talks to input and output devices.

Examples: Windows, macOS, Linux, Android, iOS.

Applications ask the OS; the OS controls the hardware.

What Happens When You Turn On a Computer?

Starting a computer is called booting.

  • Firmware (called BIOS or UEFI) is a small program stored on a chip on the motherboard. It runs first, every time.
  • It checks the hardware, then finds the operating system in storage.
  • The OS is copied from storage into RAM, because the CPU can only run programs that are in RAM.
Now the computer is ready, and the OS can start other programs — such as Python.

Machine Code: The CPU's Own Language

  • A CPU understands only machine code: instructions written in 0s and 1s.
  • Each instruction is a very small step: "put a number here", "add two numbers", "jump to another step".
  • Each CPU family (Intel, ARM in phones, …) has its own machine code.
Machine code is very hard for people to read and write. One wrong 0 or 1 changes the meaning.
Machine code — "store 5, then add 3" (Intel CPU)
10110000 00000101
00000100 00000011

Can you tell what this does? Neither can most people! This is why other languages were invented.

Assembly Language: Short Words for Machine Code

  • Assembly language uses short words, called mnemonics, instead of 0s and 1s.
  • Each assembly line matches one machine code instruction.
  • A program called an assembler turns assembly into machine code.
  • It is still tied to one CPU family, and still slow to write.
Assembly
MOV AL, 5     ; put 5 in AL
ADD AL, 3     ; add 3 to AL
Machine code (after the assembler)
10110000 00000101
00000100 00000011

AL is a register: a tiny, very fast storage place inside the CPU. MOV means move (put), ADD means add. Afterwards, AL holds 8.

High-Level Languages: Closer to Human Language

Other high-level languages: Java, C, C++, JavaScript. High-level code works on many kinds of CPUs.

Translators: From Your Code to Machine Code

The CPU cannot understand Python directly. A translator program must turn it into machine code.

TranslatorTranslates
Assemblerassembly language → machine code
Compilera whole high-level program → machine code, before it runs
Interpretera high-level program, one line at a time, while it runs

Source code = the program text that a person writes.

The Compiler

  • Translates the whole program at once, before it runs.
  • If there is an error, it reports it and no program file is made.
  • The program file can run many times without translating again.
Analogy: translating a whole book into Arabic, then printing it. Readers do not need the translator any more.

Languages usually compiled: C, C++, Go.

The Interpreter

  • Translates and runs the program one line at a time.
  • If a line has an error, it stops at that line. Lines before it have already run.
  • No separate program file is made; the interpreter is needed every time the program runs.
Analogy: a live interpreter at a meeting — translating each sentence as the speaker says it.

Languages usually interpreted: Python, JavaScript. The program that runs your Python code is called the Python interpreter.

Both do the same job — turn high-level code into something the CPU can run. They do it at different times.

See the Interpreter at Work

Code
print("Start")
print(5 + 2)
print(total)      # total does not exist
print("End")
Output
Start
7
NameError: name 'total' is not defined

Step by step

  1. Line 1 runs: Start appears.
  2. Line 2 runs: Python calculates 5 + 2 and shows 7.
  3. Line 3 has an error: nothing called total exists. The interpreter stops.
  4. Line 4 never runs, so End is not shown.
A compiled language would report the problem before showing anything.

What Happens Inside the Computer?

  1. When you press Run, the OS copies the Python interpreter and your file from storage into RAM.
  2. The interpreter reads your code and turns each line into machine instructions. The CPU runs them.
  3. print sends the text to the screen (output).
  4. When the program ends, the OS frees its part of RAM.
Every part from today works together: storage, RAM, CPU, OS, interpreter, and output.

Common Mistakes (1): Wrong Ideas About Computers

Incorrect

"My laptop has 512 GB of memory."

Why? 512 GB is usually the storage (SSD). Memory (RAM) is smaller, such as 16 GB.

Correct

"My laptop has 16 GB of RAM and a 512 GB SSD."

Incorrect

"More storage makes programs run faster."

Why? Speed depends mostly on the CPU and the amount of RAM. Storage size decides how many files you can keep.

Incorrect

"The CPU understands Python."

Why? The CPU understands only machine code. The interpreter translates Python for it.

Correct

"The Python interpreter turns my code into instructions that the CPU can run."

Incorrect

"My work is safe while I type, even if I do not save."

Why? Unsaved work is only in RAM, and it is lost when the power goes off. Save often.

Common Mistakes (2): Your First Program

Incorrect 
Print("Hello")
NameError: name 'Print' is not defined

Why? Python is case-sensitive: Print ≠ print.

Correct 
print("Hello")
Incorrect 
print(Hello)
NameError: name 'Hello' is not defined

Why? Without quotes, Python does not treat Hello as text.

Correct 
print("Hello")
Incorrect 
print("Hello)
SyntaxError: unterminated string literal

Why? The closing quote is missing.

Correct 
print("Hello")
A syntax error means the code breaks Python's writing rules, like a spelling or grammar mistake.

Worked Example 2: Following a Program Through the Computer

Code — saved as total.py
qty = int(input("How many books? "))
price = 4.5
print("Total:", qty * price, "KD")
Sample run
How many books? 3
Total: 13.5 KD
  1. Storage → RAM: the OS loads the interpreter and total.py.
  2. Input: the user types 3 on the keyboard; int turns it into a number.
  3. RAM: qty holds 3 and price holds 4.5.
  4. Process: the CPU multiplies 3 × 4.5 = 13.5.
  5. Output: print shows the result on the screen.

Do not worry about every detail of this code yet. You will learn input, int, and variables in the next lectures.

Think About It

1. Why does a computer need RAM if it already has storage?
Storage is too slow for the CPU to work from directly. Programs and data are copied into fast RAM while they are being used.
2. A Python program and a phone app both run on your phone. Who decides which one gets the CPU?
The operating system. It shares CPU time and RAM between all running programs.
3. Why is it useful that Python runs one line at a time while you are learning?
You can run your code immediately, see results line by line, and find exactly where an error happened.

What You Should Remember

  1. Hardware = physical parts; software = programs.
  2. Computers follow the input → process → output model, and store data.
  3. The CPU runs instructions; RAM holds what is used now (lost at power off); storage keeps files.
  4. The operating system manages the hardware and runs programs. Booting loads it into RAM.
  5. The CPU understands only machine code (0s and 1s). Assembly uses short words; Python is high-level.
  6. A compiler translates the whole program first; an interpreter translates and runs line by line. Python uses an interpreter.
  7. To run Python: write → save (.py) → run → interpreter + CPU → output.
